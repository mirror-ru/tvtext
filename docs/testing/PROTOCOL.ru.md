# Сетевой протокол TVText

Клиенты TVText и приёмник на телевизоре общаются по TCP с TLS 1.2 и закреплённым сертификатом, порт `45831`. Обнаружение телевизоров выполняется отдельно через mDNS; учётные данные отправляются только после проверки отпечатка сертификата ТВ.

## Формат кадра

Каждое сообщение начинается с 4-байтовой длины тела в сетевом порядке байтов (big-endian). Строки протокола v1 кодируются в UTF-8 и предваряются 4-байтовой длиной в байтах.

Тело запроса: версия (1 байт, `1`), команда (1 байт: сопряжение `1`, состояние `2`, ввод `3`, отзыв доступа `4`), учётные данные (до 256 байт), ID устройства/запроса (до 128 байт), текст (до 32 768 байт).

Тело ответа: версия, код результата, флаг готовности (`0` или `1`), сообщение (до 4096 байт), токен (до 256 байт), целевое приложение (до 1024 байт), ID телевизора (до 128 байт). Коды: `0` успех, `1` отказ в авторизации, `2` сопряжение закрыто, `3` неверный код, `4` поле ввода не готово, `5` приёмник отключён, `6` неверный запрос, `9` результат доставки неизвестен.

Максимальное тело кадра — 65 536 байт. Приёмник отклоняет неподдерживаемую версию, некорректный UTF-8, неверные длины и флаг готовности, а также лишние байты. ID запроса предотвращает повторную вставку текста при повторе того же запроса.

## Общий эталон совместимости

Файл `tests/shared/protocol/v1-vectors.txt` используется тестами Android TV, Android mobile и Windows. В нём есть компактный запрос с кириллицей, emoji и переводом строки, а также ответ. Каждый клиент должен совпасть с эталонными байтами и прочитать тот же ответ. При изменении формата обновляйте реализации и эталон одновременно.

## Локальная диагностика соединения

Диагностика должна показывать только этап сбоя: TCP-подключение, TLS/проверка сертификата или ответ протокола. Нельзя включать в неё текст, код сопряжения, учётные данные, токены, отпечатки сертификатов или сетевые адреса.
