# Проверка совместимости

[English version](COMPATIBILITY.md)

Оба APK требуют Android 9 / API 28 или новее. Это условие сборки, а не подтверждение проверки всех прошивок. Доступен изолированный эмулятор Android 14 / API 34. Образы Android 9–13 и 15–16 и реальные ТВ в текущем окружении отсутствуют; их результаты остаются **«не проверено»**.

| Android приёмника | Способ ввода | Доступные подтверждения |
| --- | --- | --- |
| 9–12L / API 28–32 | Действие «Вставить», без запасной замены всего поля | Старый механизм проверяется на API 34; запуск на API 28–32 не выполнен |
| 13 / API 33 | Соединение ввода специальных возможностей | Запуск на API 33 не выполнен |
| 14 / API 34 | Соединение ввода специальных возможностей | Инструментальные проверки на эмуляторе; см. свежий отчёт о тестах |
| 15–16 / API 35–36 | Соединение ввода специальных возможностей | Запуск не выполнен |
| Реальный Google TV / прошивка производителя | Зависит от Android и поля приложения | В этом окружении не проверено |

`test-compatibility.ps1` последовательно запускает мобильный и телевизионный наборы на явно указанных изолированных эмуляторах и записывает JSON-матрицу: пройдено, ошибка, не запускалось. Скрипт задаёт размеры телефона и ТВ и восстанавливает прежние переопределения размера/плотности даже при ошибке. Он не скачивает образы, не управляет реальными устройствами и не засчитывает отсутствующие проверки. Мобильные тесты сообщают фактический API. Наборы устанавливают тестовые приложения и меняют тестовые настройки — используйте одноразовые AVD.

```powershell
.\test-compatibility.ps1 -Device emulator-5580 `
  -Artifacts '.\dist' -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk'
```

UI-наборы проверяют сопряжение, локальное состояние, тему/язык, фокус и отправку. Телевизионный набор отдельно проверяет старый механизм: курсор внутри непустого поля, замену выделения, поле с SetText без Paste, отказ Paste и восстановление буфера после быстрых отправок/копирования пользователем. Проверка старого механизма на API 34 не доказывает работу политики буфера и службы на API 28–32.

Для каждого реального ТВ записывайте модель, прошивку/номер сборки, Android/API, клавиатуру, приложение/версию целевого поля, платформу отправителя и точные хеши APK/EXE. Проверяйте:

1. Пустое поле, курсор внутри непустого поля, выделенный текст, Unicode/несколько строк и поле с отказом вставки; при ошибке черновик сохраняется.
2. Gboard и хотя бы одно нестандартное поле: WebView или поиск отдельного приложения. Поддержку каждого редактора нужно подтверждать отдельно.
3. Сопряжение/проверку отпечатка, несколько клиентов, смену ТВ, отвязку с обеих сторон и невозможность уведомить ТВ об отвязке.
4. Сон/пробуждение, перезапуск приложения/службы, обрыв/восстановление Wi-Fi, смену DHCP-адреса, блокировку обнаружения и ручное обновление. После ошибки текст не должен отправляться повторно автоматически.
5. Навигацию пультом и видимый фокус, RU/EN, темы, поворот телефона/планшета и крупный системный шрифт.

Для каждого сценария фиксируйте ожидаемый и фактический результат, дату и успех/ошибку. До получения этих подтверждений совместимость с реальными ТВ остаётся непроверенной.
