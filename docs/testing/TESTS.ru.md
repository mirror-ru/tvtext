# Отчёт о проверках TVText

## Текущие артефакты 2.0.7

- APK для ТВ: `TVText-TV-2.0.7.apk`, пакет `com.tvtext.app`, код версии `27`.
- Мобильный APK: `TVText-Mobile-2.0.7.apk`, пакет `com.tvtext.mobile.app`, код версии `27`.
- Windows EXE: `TVText-2.0.7.exe`, версия `2.0.7.0`.
- Подписи APK и метаданные версий APK/EXE проверены при сборке 2.0.7.
- SHA-256: APK для ТВ `EC82FE3CF7D252A9ECC4137212608999503D4F3AE1B46337CF9A426C0038F75A`; мобильный APK `9611B084DF4840F804D578A33A3999E69F8E377083345D9C34B0263451C26209`; Windows EXE `B2B96875C0FE31980D437E7DC88AF43FB3C577A9D300ABC93D9479370D1ADBB4`.

Регрессионные проверки после ревью охватывают реальные касания в мобильном приложении, отмену жеста и уход пальца за кнопку, миграцию зашифрованных подключений и локальных имён, исчезновение отвязанного переименованного ТВ, синхронизацию активного подключения Windows и локализацию кодов ответа, восстановление буфера после быстрых вставок на ТВ и копирования пользователем.

Последний полный набор проверок был успешно пройден до пересборки 2.0.7 только с обновлением метаданных: Windows/TLS — `build/test-269701adc95b4d3e98de29408c432350`, мобильные JVM/TLS/UI — `build/mobile-test-cd3b2bcdebf141a58de58b492c965e6d`, TV UI — `build/tv-ui-test-5cba03cdecc0460c9dc2f831d7f03663`. Проверки интерфейсов APK выполнены на изолированном эмуляторе Android 14. Версия 2.0.7 отдельно не тестировалась, поскольку изменились только метаданные выпуска, без изменений протокола и исходников выполнения.

Подробная история проверок 2.0.4 приведена ниже для справки.

## Историческая проверка версии 2.0.4

Для выпуска 2.0.4 проверены:

- версии EXE `AssemblyVersion`, `FileVersion` и `ProductVersion`: `2.0.4.0`;
- версии обоих APK: `versionName 2.0.4`, `versionCode 24`;
- метаданные APK, подписи v3, zipalign и совпадение сертификата с предыдущей релизной подписью;
- имя файла конфигурации Windows `TVText-2.0.4.exe.config`;
- структура исходников с тестами в `tests/android-tv/`, `tests/android/` и `tests/windows/`.

После разделения тестов полный набор Windows/ТВ и мобильный JVM-набор были запущены на релизном коде и завершились успешно. Сборка 2.0.4 меняет только версии и не меняет протокол или интерфейс.

## Запуск проверок

Из корня проекта:

```powershell
.\test.ps1 -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk'
.\test.ps1 -Shrink -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk'
.\test-mobile.ps1 -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk'
```

Device-набор разрешено запускать только на явно указанном эмуляторе:

```powershell
.\test-mobile.ps1 -Device emulator-5580 `
  -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk' `
  -AppApk '.\dist\TVText-Mobile-2.0.7.apk'
```

`test.ps1` компилирует Windows-клиент на C# и Kotlin-фикстуру ТВ, запускает локальные TLS/DNS-SD проверки и создаёт окна Windows Forms за пределами экрана. `test-mobile.ps1` сначала выполняет JVM-проверки протокола; с `-Device` дополнительно собирает instrumentation APK, устанавливает релизный APK и запускает тесты в выбранном эмуляторе.

## Покрытие Windows и ТВ

Проверяются:

- длины кадров, UTF-8, ограничение размера текста, повреждённые ответы и постоянный идентификатор ТВ;
- TLS 1.2, pinning сертификата, срок действия сопряжения, блокировка после десяти ошибок, замена и отзыв ключей, режим только IPv4 и dual-stack;
- идемпотентность вставки, подавление дубликатов, отмена очереди, абсолютные тайм-ауты, пауза приёма и отсутствие повтора после неясного результата;
- зашифрованные профили нескольких ТВ, атомарная запись, сохранение повреждённого файла, параллельная запись, восстановление адреса после смены IP и изоляция ТВ;
- Windows DNS-SD browse/resolve, отмена, освобождение нативных дескрипторов и постоянные идентификаторы установки;
- выбор ТВ, навигация клавиатурой, accessibility, сопряжение и повторное сопряжение, переименование, RU/EN, Enter/Shift+Enter, сохранение черновика, маршрутизация отправки и отсутствие фонового опроса;
- компоновка Windows при 96 и 120 DPI и программном масштабировании 100–200%, 0/1/2/3/9 ТВ, длинные имена, список на три строки и редактор на три строки.

Accessibility-фикстура ТВ находится в `tests/android-tv/fixture/`. Это контролируемое Android-поле для проверки вставки, а не стороннее приложение на реальном ТВ.

## Покрытие мобильного приложения

JVM-набор сравнивает кодек телефона с производственным протоколом ТВ и проверяет строгую обработку UTF-8/кадров, pinning TLS, сопряжение, UUID, независимые ТВ, отзыв ключа, отмену и отсутствие автоматического повтора текста.

Instrumentation запускается на настоящем релизном мобильном APK в эмуляторе Android 14 AOSP ATD. Проверяются NSD, Android Keystore AES-GCM, повреждённые профили, маршрутизация Unicode только выбранному ТВ, очистка после успеха, сохранение текста после ошибки, редактирование во время отправки, локальное переименование, диалоги отвязки и повторного сопряжения, RU/EN, поворот и снимок экрана. Компоновка телефона и планшета проверена в портретной и альбомной ориентациях.

## Среда и границы

Эмулятор использовал API 34; `minSdk 28` компилируется и проходит через производственные пути кода. Device-тесты не работают с физическим телефоном или ТВ. Локальные TLS-фикстуры слушают только loopback-порты 45831–45833; реальные ключи ТВ и внешняя сеть не используются.

Прошивка Google TV, Gboard, поведение специальных возможностей производителя, сон/пробуждение и фильтры сторонних полей требуют отдельной проверки по Wi-Fi. Приложение может изменить или отклонить текст после передачи в активное Android-поле. Если активного поля нет, запрос отклоняется и позднее не воспроизводится.

Параметр `-Shrink` проверяет R8-сжатый JVM-код фикстуры с правилами сохранения приложения. Он не заменяет запуск Android DEX на устройстве. Результаты тестов, ключи фикстур, скриншоты и временные профили записываются в `build/` и исключены из Git через `.gitignore`.
