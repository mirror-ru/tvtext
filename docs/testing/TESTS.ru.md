## Локальные проверки доработок — 25 октября 2026

- Добавлены проверки ошибки записи Windows: подтверждённый адрес и черновик остаются рабочими в сеансе, прежний файл сохраняется, обычный сброс статуса не скрывает ошибку сохранения, успешная запись снимает предупреждение.
- Фокус окон вне экрана проверяется по активному элементу с ограниченным ожиданием обработки событий; нативный фокус проверяется, когда тестовое окно им владеет. Тест не назначает ожидаемый фокус самостоятельно.
- Дочерний процесс с PASS и последующим кодом 7 отклоняется. TLS-стенд требует одновременно нулевой код завершения и заключительный маркер проверок. Исключения нативных тестов выводятся в stderr вместо системного окна.
- Мобильный каталог проверяется на закрытое состояние, изоляцию ключей от объявлений обнаружения, ошибки записи сопряжения/отвязки/имени/адреса, локальные имена и повторное обнаружение без лишних сопряжений.
- На ТВ проверяются вставка у курсора/вместо выделения, отсутствие или отказ Paste без запасного SetText, восстановление пустого/непустого буфера после быстрых вставок и копирования пользователем.
- Помощники выпуска отклоняют лишние файлы, несовпадение контрольных сумм и другой сертификат APK. Проверки инструментов также запускаются в Windows PowerShell 5.1.
- `prepare-release.ps1` собирает и проверяет выпуск локально; `test-compatibility.ps1` записывает фактические API и недоступные окружения. См. [сборку](../building/BUILD.ru.md) и [матрицу/ручную проверку совместимости](COMPATIBILITY.ru.md). Результаты реального ТВ не выводятся из тестов эмулятора.

## Запуск проверок

Из корня проекта:

```powershell
.\test.ps1 -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk'
.\test.ps1 -Shrink -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk'
.\test-mobile.ps1 -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk'
```

Device-набор разрешено запускать только на явно указанном эмуляторе:

```powershell
.\test-mobile.ps1 -Device emulator-5580 `
  -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk' `
  -AppApk '.\dist\TVText-Mobile-2.0.9.apk'
```

`test.ps1` проверяет функции сборщика, компилирует Windows-клиент на C# и Kotlin-фикстуру ТВ, запускает локальные TLS/DNS-SD проверки и создаёт окна Windows Forms за пределами экрана. `test-mobile.ps1` сначала выполняет JVM-проверки списка устройств и протокола; с `-Device` дополнительно собирает instrumentation APK, устанавливает соответствующий APK приложения и запускает тесты в выбранном эмуляторе. `test-tv-ui.ps1` запускает instrumentation-набор ТВ. Оба device-сценария до установки проверяют файл сведений рядом с APK и точное совпадение хешей JAR и исходников.

## Покрытие Windows и ТВ

Проверяются:

- длины кадров, UTF-8, ограничение размера текста, повреждённые ответы и постоянный идентификатор ТВ;
- TLS 1.2, pinning сертификата, срок действия сопряжения, блокировка после десяти ошибок, замена и отзыв ключей, режим только IPv4 и dual-stack;
- идемпотентность вставки, подавление дубликатов, отмена очереди, абсолютные тайм-ауты, пауза приёма и отсутствие повтора после неясного результата;
- зашифрованные профили нескольких ТВ, атомарная запись, сохранение повреждённого файла, параллельная запись, восстановление адреса после смены IP и изоляция ТВ;
- Windows DNS-SD browse/resolve, отмена, освобождение нативных дескрипторов и постоянные идентификаторы установки;
- выбор ТВ, навигация клавиатурой, accessibility, сопряжение и повторное сопряжение, переименование, RU/EN, Enter/Shift+Enter, сохранение черновика, маршрутизация отправки и отсутствие фонового опроса;
- компоновка Windows при 96 и 120 DPI и программном масштабировании 100–200%, 0/1/2/3/9 ТВ, длинные имена, список на три строки и редактор на три строки.

Accessibility-фикстура ТВ находится в `tests/android-tv/fixture/`. Это контролируемое Android-поле для проверки вставки, а не стороннее приложение на реальном ТВ.

## Покрытие мобильного приложения

JVM-набор сравнивает кодек телефона с производственным протоколом ТВ и проверяет строгую обработку UTF-8/кадров, pinning TLS, сопряжение, UUID, независимые ТВ, отзыв ключа, отмену и отсутствие автоматического повтора текста.

Instrumentation запускается на настоящем релизном мобильном APK в изолированных эмуляторах Android 9 AOSP, Android 12 AOSP и Android 14 AOSP ATD. Проверяются NSD, Android Keystore AES-GCM, повреждённые профили, маршрутизация Unicode только выбранному ТВ, очистка после успеха, сохранение текста после ошибки, редактирование во время отправки, локальное переименование, диалоги отвязки и повторного сопряжения, RU/EN, поворот и снимок экрана. Компоновка телефона и планшета проверена в портретной и альбомной ориентациях.

## Среда и границы

Device-прогоны используют эмуляторы API 28, API 31 и API 34; описанная выше регрессия буфера на API 31 остаётся падающей. API 28 проверен на тестовом образе AOSP, без подтверждения всех прошивок производителей. Device-тесты не работают с физическим телефоном или ТВ. Локальные TLS-фикстуры слушают только loopback-порты 45831–45833; реальные ключи ТВ и внешняя сеть не используются.

Прошивка Google TV, Gboard, поведение специальных возможностей производителя, сон/пробуждение и фильтры сторонних полей требуют отдельной проверки по Wi-Fi. Приложение может изменить или отклонить текст после передачи в активное Android-поле. Если активного поля нет, запрос отклоняется и позднее не воспроизводится.

Параметр `-Shrink` проверяет R8-сжатый JVM-код фикстуры с правилами сохранения приложения. Он не заменяет запуск Android DEX на устройстве. Результаты тестов, ключи фикстур, скриншоты и временные профили записываются в `build/` и исключены из Git через `.gitignore`.
