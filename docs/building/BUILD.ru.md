# Сборка TVText

[English version](BUILD.md)

Сценарии PowerShell запускаются из корня проекта на Windows и не загружают зависимости.

## Версия и инструменты

`version.json` — единственный источник версии приложений и кода версии Android. Для следующего выпуска измените оба поля. Сборщик передаёт их упаковщику Android и создаёт атрибуты версии и манифест Windows в `build/`, не изменяя отслеживаемые исходники. `windows/app.manifest` является шаблоном; его обрабатывают сценарии сборки и тестов.

`toolchain.json` фиксирует JDK 21.0.10, Kotlin `2.2.20-release-333`, платформу Android `android-36.1` ревизии 1 и build-tools 37.0.0. При несовпадении версий сценарии завершаются с понятной ошибкой. Установите указанные версии и задайте расположение через `-Jdk`, `-Kotlin` и `-Sdk`. Обновление инструментов выполняется явной правкой `toolchain.json` с последующей сборкой и тестами. Фиксация версий исключает случайное обновление инструментов, но не гарантирует побайтовую воспроизводимость подписанных сборок.

По умолчанию используются JDK и Kotlin из Android Studio, а SDK — из `%LOCALAPPDATA%\Android\Sdk`. Можно менять пути; версии проверяются по файлу настроек. Компилятор Windows берётся из установленного .NET Framework и обновляется вместе с Windows.

## Выбор платформы

```powershell
.\build.ps1 -Target Windows
.\build.ps1 -Target TV -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk'
.\build.ps1 -Target Mobile -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk'
.\build.ps1 -Target All -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk'
```

Для `Windows` нужен только компилятор C#: Android-инструменты не проверяются, ключ подписи APK не создаётся. Android-целям нужны зафиксированные Android/JVM-инструменты; при первой сборке создаётся локальный ключ подписи. Для сохранения прежней подписи восстановите вместе `.local/signing.p12` и `.local/signing-password.txt`. Неполная пара файлов вызывает ошибку, а не заменяется новым ключом.

По умолчанию результат помещается в `dist/`; путь можно изменить через `-Output`. Каждая сборка использует отдельную папку `build/run-*/`. В релиз загружаются два APK, EXE и его файл `.exe.config`.

Исходники мобильного приложения находятся в `android-mobile/`, промежуточный JAR — в `build/run-*/android-mobile/app.jar`. Исходники мобильных тестов находятся в `tests/android-mobile/`. Идентификатор приложения Android остаётся `com.tvtext.mobile.app`.

## Локальная подготовка выпуска

Отпечаток исходников фиксируется до сборки и сверяется после неё и после тестов. В обоих режимах, включая `Core`, проверяются записи соответствия APK, JAR и исходников; сохраняйте промежуточные JAR до завершения подготовки выпуска. При изменении исходников требуется новая сборка.

Команда `prepare-release.ps1 -Device emulator-5580 -Sdk '<путь к SDK>'` собирает три приложения, проверяет версии, ограничения SDK, выравнивание и сертификаты APK, затем запускает Windows/TLS и оба набора Android UI. По умолчанию проверки полные и требуют явно выбранного изолированного эмулятора. `-Tests Core` явно пропускает Android UI и отражает это в отчёте; Windows/TLS и мобильные JVM-тесты остаются обязательными.

После успешных проверок скрипт создаёт новую папку кандидата в `outputs/`. Можно указать другой новый путь через `-Output`; существующие папки отклоняются. В результате находятся два APK, EXE, конфигурация EXE, `SHA256SUMS.txt` и `release-report.json`. Локальные сведения о сборке APK/JAR остаются в `build/`. Ключи, пароли, тестовые APK и локальные пути JAR в папку кандидата не попадают. Загрузки в GitHub и коммита нет.

`release-signing.json` содержит публичный отпечаток сертификата APK для проверки обновлений. Его безопасно хранить в Git; изменение означает осознанную смену подписи. Состояние Authenticode для Windows записывается в отчёт без утверждения, что файл подписан: текущий EXE не подписан. Проверки эмуляторов отделены от ручных проверок реального ТВ: [проверка совместимости](../testing/COMPATIBILITY.ru.md).

## Соответствие APK и device-тестов

Рядом с каждым APK создаётся `<имя>.apk.build.json`. В нём записаны SHA-256 APK, путь и хеш его `app.jar`, отпечаток исходников приложения и сборщика, версия и настройки инструментов. Ключей подписи, паролей и данных сопряжения в нём нет. Это локальная проверка согласованности, а не криптографическое подтверждение происхождения файла. Файл нужен для тестов и не включается в релиз.

Пути в отпечатке сортируются одинаково в Windows PowerShell 5.1 и PowerShell 7. После обновления алгоритма и исходников старые сведения о сборке больше не соответствуют текущему проекту: пересоберите APK и его запись с прежним ключом подписи.

```powershell
.\test-mobile.ps1 -Device emulator-5580 `
  -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk' `
  -AppApk '.\dist\TVText-Mobile-2.0.10.apk'
.\test-tv-ui.ps1 -Device emulator-5580 `
  -Sdk 'C:\Users\YOUR_USER\AppData\Local\Android\Sdk' `
  -AppApk '.\dist\TVText-TV-2.0.10.apk'
```

Сценарии находят `app.jar` по этому файлу. Через `-AppJar` можно указать перемещённую копию, но её хеш должен совпадать. До установки на эмулятор отклоняются отсутствующие сведения о сборке, изменённый APK/JAR, другая платформа, версия или набор инструментов, а также изменения исходников приложения и сборщика. Старые APK без файла сведений нужно пересобрать. После изменения исходников также нужна новая сборка. Сохраняйте соответствующую папку `build/run-*/` до окончания тестов.

Принимаются только явно указанные изолированные эмуляторы. Мобильным JVM-тестам без устройства не нужны APK, SDK и ключ подписи. `test.ps1` запускает и `tests/tooling/BuildTests.ps1`: проверку версии, независимости Windows от Android и отклонения несовпадающих APK/JAR. Отдельный запуск этих проверок:

```powershell
.\tests\tooling\BuildTests.ps1
```
